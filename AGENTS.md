# Repository Guidelines

## Architecture

`server/src/practiq_ai/` is the sole Python 3.14+ LangGraph AI document import service. Keep its format extractors, shared parser graphs, structured contracts, local file storage and model usage accounting together. `webapp.py` exposes same-origin upload and artifact routes; The single-process open-source LangGraph runtime consumes RabbitMQ document-run deliveries through a PostgreSQL transactional outbox; PostgreSQL owns task/run records, checkpoints, Store and grading receipts; `/ok` and `/ready` are health checks. Do not restore official Agent Server APIs or Redis.

`web/` is the independent React/Vite frontend served by the AI service. The approved target is an authenticated user portal plus a Web administration area, reusing the existing same-origin document-import APIs. The user portal includes account settings, explicit source upload, personal task progress, saved-result review, personal question-bank ZIP download and usage history. Administration includes user activation/deactivation, registration policy, task inspection and explicit recovery, provider usage, non-secret system configuration and audit records. Model provider configuration and credentials remain service-side. Do not add Tauri imports, online practice or a second document parser.

`app/` is the independent offline Tauri 2 practice application (React/Vite/shadcn/ui/TypeScript, Rust, SQLite). It imports question-bank ZIP packages using the existing AI JSON contract. It contains no Python service, LibreOffice runtime or AI document-import UI. Explicit subjective AI grading uses Rust reqwest to call a user-configured OpenAI-compatible Chat Completions API, or the independently running service for existing deployments; offline practice needs no service. The app targets macOS only. Use desktop layouts. Keep SQLite and native file access behind typed Tauri commands. Preserve imported review flags and immutable practice snapshots. Images are immutable content-addressed files; SQLite stores their metadata. Write and verify images before committing database references. Backups include practice data and images, but exclude AI task state and credentials. App data uses `v4/` and SQLite schema 11; initialize only empty databases and reject older databases/backups without migration. Preserve old directories, task files and credential namespaces untouched. App grading connection settings (service URL or optional `model` with `base_url`/`model_id`) persist in the separate versioned `v4/service-settings-v1.sqlite` sidecar, without modifying the schema-11 practice database or its legacy provider columns. Backups carry optional strictly validated version-1 grading connection settings in the existing version-4 manifest; old schema-11 backups remain supported. A durable pending restore record is resolved before startup opens the practice database for writes; the current instance blocks database operations while recovery remains required. Only an empty version-0 sidecar with no SQLite objects is treated as absent on reads and initialized on explicit writes; never replace unknown nonempty settings databases. Access tokens and user-supplied model API keys stay in macOS Keychain and are excluded from backups. Only explicit grading or retry may start app model work.

The approved service direction is multi-user deployment with email/password accounts and separate user and administrator permissions. This is an implementation target, not a claim that authentication or administration already exists. Reuse the existing service, PostgreSQL, local storage and document runtime; do not introduce a second backend or parser. Do not add phone accounts, point billing, commercial products, checkout or payment dependencies. Keep provider usage records, model-call budgets, explicit recovery and partial export. The current service database schema is 6; account and ownership changes require a new versioned schema and an explicit offline upgrade with database/storage backups. Preserve existing data and historical account/payment tables. Never assign existing tasks, uploads, banks or unsettled calls to the first registered user, silently delete them, or infer identity from historical account fields. Default to preserving the old deployment and using a fresh database/storage/vhost for the multi-user deployment; migration requires an operator-approved ownership mapping and must leave unmapped data inaccessible to users. `server/docs/personal-use.md` describes the existing personal deployment and must be updated alongside implementation. Material-question groups are document content, not study groups.

### User system and administration target

The approved first release does not send email or verify addresses. Email is an unverified login identifier. Changing it requires the current password. Password recovery uses an explicitly issued single-use administrator reset link after out-of-band identity checks.

New users receive 50 free document-recognition pages in total, with no daily refill. Reserve pages before paid submission, retain unknown outcomes, and do not double-count saved receipt replay. Daily call/concurrency safety limits remain separate. Administrators may adjust total page allowances explicitly; do not add billing or checkout.

- Provide email/password registration, login/logout, administrator-assisted password reset and revocable server-side sessions. Administrators control whether public registration is enabled. Bootstrap the first administrator through an explicit operator action, never by making the first public registrant an administrator. Use established password-hashing and cryptographic-token primitives; Reset tokens must be bounded, single-use and expiring. Do not store plaintext passwords or raw authentication tokens in databases or logs.
- Browser authentication uses same-origin HttpOnly session cookies with appropriate SameSite and production Secure settings, CSRF protection and login/reset abuse limits. Do not store authentication secrets in browser storage or URLs, except short-lived verification/reset links whose tokens must be excluded from logs and referrers. Disabled users and revoked sessions must immediately lose access. Password reset revokes existing sessions.
- Enforce authentication, user ownership and administrator permissions on the server, including task lists, uploads, task mutations, artifacts, banks, grading and usage. A task ID or storage reference is not authorization. Resolve ownership from the authenticated identity, not caller-supplied user IDs. Administrative access must be explicit and audited; never expose provider credentials, password hashes or authentication tokens in administrative responses.
- Keep the macOS App offline and independent: no login requirement for local practice, ZIP import or direct model grading. Authentication changes to optional service-mode grading require a documented compatible connection flow and corresponding native changes; never silently reinterpret or delete legacy credentials or settings.
- Cover account lifecycle, role checks, cross-user access denial, session revocation, CSRF, administrator bootstrap, historical ownership boundaries and user/admin frontend interactions with focused tests. Update generated shared contracts, deployment documentation and recovery procedures with implementation. Passive reads, login, migration and audit inspection must not start model work; any administrative recovery that can incur charges requires an explicit action.

## Commands

- Use an existing Python 3.14+ interpreter; no project `.venv`. Set `AI_PYTHON` when needed.
- `make install`: install AI and development dependencies into that interpreter.
- `make server-dev`: run Uvicorn on loopback with PostgreSQL and RabbitMQ, loading `.env`.
- `make test` / `make test-server`: AI tests without external model calls.
- `make install-locked`: install locked runtime/development dependencies into the selected interpreter without a project `.venv`.
- `make upgrade-db UPGRADE_BACKUP=/absolute/path/to/verified/bundle`: explicitly upgrade service schema 1–5 to 6 offline under runtime ownership; verify and retain database/storage backups.
- `make verify`: lockfile consistency, Ruff, Pyright, evaluation fixtures, one test run with 90% coverage, recovery probes and package build. Reports go to `server/reports/checks/`, including on test failure.
- `make audit` / `make image-check`: audit locked dependencies (network required) / build the Docker image without publishing.

- `make app-install` / `make app-dev`: install locked desktop dependencies / start the Tauri desktop application.
- `make app-check AI_PYTHON=...`: on macOS, check shared AI contracts, frontend interactions, host Rust integration tests and Clippy. Other native app targets are unsupported.
- `make app-build`: build a native macOS package without publishing.
- `make web-install` / `make web-dev`: install locked Web dependencies / start the loopback import frontend with a proxy to the independent service.
- `make web-check` / `make web-build`: check the Web frontend / build its static assets for the independent service.

## Module Conventions

### AI service (`server/`)

- Layout: `webapp.py` same-origin upload/artifact routes, `config.py` environment settings, `graphs/` workflows, `extractors/` format readers, `contracts.py` shared models, `runtime.py` graph registration, `database.py` PostgreSQL task records, tests in `tests/`. Do not add another parser or restore product APIs.
- Style: four-space indentation, type annotations and small single-responsibility modules; `snake_case` functions/variables, `PascalCase` classes and Pydantic models, `UPPER_CASE` constants; keep public payload fields compatible with the existing camelCase API contracts; prefer async for I/O and reuse shared errors and models instead of duplicating validation. Run the configured Ruff checks and type-check with `pyrightconfig.json`.
- Tests: pytest with `pytest-asyncio` in automatic mode, named `test_<behavior>` with fixtures or fakes close to each scenario and shared fakes in `tests/support.py`, not other test modules. Runtime tests explicitly request the `disposable_databases` fixture; pure tests must not start Docker. Cover success paths, validation failures, resumability and storage/checksum boundaries; never call real LLM services (monkeypatch them as existing tests do). Service CI exercises PDFium and the deployed Office adapter; desktop CI verifies that final packages contain no Python or LibreOffice runtime. Keep the 90% coverage threshold and add a focused regression test for every behavior change.

### User and administration Web frontend (`web/`)

- Derive shared types from `server/src/practiq_ai/contracts.py` using the existing exporter. Do not hand-maintain duplicate API schemas.
- Use same-origin fetches with the authenticated session and CSRF protection for mutations, bounded files and verified binary artifacts. Never render raw document/model HTML, accept arbitrary download URLs or persist provider credentials in URLs, browser storage or logs. User and administration routes must handle expired sessions and permission failures without automatically replaying mutations.
- File selection, GET polling and ZIP export are passive. Start import, resume, retry and parse again are explicit actions. Preserve failed/unknown outcomes and request IDs; do not automatically replay uncertain mutations.
- Reuse the octopus brand, Lucide icons and standard accessible desktop layouts. Test upload/result/control behavior with model substitutes.

### Practice app (`app/`)

- Validate all native command inputs. File access begins with a native file picker; imported content cannot request arbitrary SQL, file access or network access.
- Preserve nulls, quality warnings, source associations and practice snapshots. Unreviewed content may be practised; incomplete/unavailable answers must not become automatically incorrect.
- Keep databases out of the repository. Use temporary directories in integration tests, including resource import and restore tests.
- Use the existing octopus brand asset, Lucide (`lucide-react`) for functional icons, existing shadcn components and standard CSS layout. Preserve accessible desktop interactions.

## Boundaries

Preserve strict Pydantic inputs, bounded uploads, path and checksum validation, partial-result details, checkpoint resumability and per-call usage on success and failure. Never inject raw document/model HTML. Do not add another source-document parser or a product compatibility layer. The desktop JSON importer must follow the existing AI contracts.

Bind services to loopback. Multi-user deployment uses a trusted HTTPS reverse proxy; do not expose internal PostgreSQL, RabbitMQ or worker endpoints. Keep document-import provider credentials server-side. App direct grading keys belong only to the native credential store in the separate `ai-model-key-v1-` account namespace, never the frontend, SQLite, logs or backups. Never commit environment secrets. Preserve existing files, database volumes and unrelated worktree changes. Use local file storage; preserve reference and checksum validation. Do not restore cloud object-storage backends. Local AI storage resolves relative to `server/`; production must use a persistent absolute path.

Update relevant documentation and focused tests with behavior changes. Follow `CONTRIBUTING.md` for issues and pull requests. Issues must use the applicable template in `.github/ISSUE_TEMPLATE/`; pull requests must use `.github/PULL_REQUEST_TEMPLATE.md`. This applies to submissions through the GitHub UI, CLI, or API. Preserve template fields and sections, explain non-applicable items, and mark checklist items complete only when verified.

The service accepts PDF, TXT, Markdown, PNG/JPEG, Word (.doc/.docx), PPT (.ppt/.pptx) and Excel (.xls/.xlsx) through Tencent SubmitMultimodalDocParseJob / DescribeMultimodalDocParseJob. Reject new CSV uploads/tasks while preserving saved records and banks. Every new supported import uses Tencent before question structuring; no local recognition fallback or user-selectable Office conversion mode is permitted. Verify immutable source hashes and durable submission intents before paid work; an uncertain submission is never automatically replayed. Local directories remain the default. AI_TENCENT_INPUT_MAX_BYTES is at most 150 MiB; local Base64 has an additional 8 MiB cap. Private COS is explicit advanced opt-in via AI_TENCENT_COS_ENABLED: when enabled, every source uses private staged objects and signed FileUrl, with no automatic transport fallback. COS is temporary input staging, never the authoritative storage backend; retain local source/result references and checksums. Validate source-type limits, preserve upload intents and safe cleanup, and never persist signed URLs. TXT/Markdown select output type 2; layout/resource inputs select 9 to retain JSON coordinates and XML image associations. Split larger inputs before the first submission: UTF-8 text boundaries, rendered PDF pages and lossless image tiles. Oversized Office alone reuses the isolated LibreOffice PDF adapter, with hidden sheets/slides included; smaller Office goes directly to Tencent. Preserve ordered split receipts, source byte/pixel ranges and original-page references. Only Tencent text exactly matching the original may reuse original-text source-presence and deduplication proofs; differing evidence stays reviewable as OCR pages. Models associate fixed Tencent figure IDs and cannot invent or change their coordinates. Reuse the isolated `office` worker and existing format extractors; do not add parser graphs, python-docx, openpyxl or UNO. Executable/version configuration comes only from trusted service environment, never HTTP or desktop preferences. Preserve original source hashes, derived manifest checksums, deterministic manifest order, engine identity, process cleanup and shared limits across conversion and parsing. The explicit Web Start import action authorizes normalization and AI submission without a second confirmation dialog; merely selecting a file must not submit it to a model. Retain upstream licenses and source links in the independent deployment. Desktop packages must not include or discover Python/LibreOffice installations. Do not store executable preferences in SQLite; reject backups containing them. Offline question-bank ZIP import is under Settings > Import and restore alongside full study-data restoration; bank import appends content, while full restoration requires replacement confirmation.

Subjective grading is allowed only after an explicit user grading or retry action. Parsing still extracts supplied answers, scores and rubrics without solving questions. The optional `generateAnswers` import flag defaults to false; only a checked flag plus explicit Start authorizes a separate post-extraction step to fill missing answers/analysis. Preserve supplied fields, source proofs and references; generated content is marked for review and shares existing durable receipts and per-task model budgets. Passive reads/export must never generate answers. Grading requires a reference answer or explicit rubric; missing evidence remains ungraded. Reuse existing scoring snapshots and safeguards. Direct grading makes one bounded model call without automatic retries; persist an unknown-result receipt before sending, bind it to the endpoint/model/prompt version, and require explicit regrading after uncertainty or a target change. Existing service mode retains its server receipts; keep exam answers, score snapshots and manual overrides local and preserve them in backups. Legacy provider settings and keys must not be interpreted as a service URL/token or deleted during this change.

## Commit Conventions

Use Conventional Commits: `<type>(<scope>): <summary>`. Allowed types are `feat`, `fix`, `docs`, `refactor`, `test`, and `chore`. Use an optional module name for `scope`, an imperative summary of at most 72 characters, and no trailing period. Example: `fix(extractors): enforce PDF page limit`. Keep each commit scoped to one concern.

The multi-user target requires authentication and server-side ownership checks for task, upload, artifact and grading APIs, plus administrator checks for administrative APIs. Public access is limited to required registration, login and password-recovery flows, their static frontend assets and non-sensitive health checks. Administrator bootstrap must not be a public endpoint. Do not expose task or provider data through health endpoints. Retain loopback bindings and cross-origin request rejection. Artifact reads require an authorized task ID and a verified reference belonging to that task. Preserve call records and unknown results; explicit resume/retry may incur provider charges. Never start models during passive reads, export, migration or backup.
