# Taro 微信小程序迁移计划

## 目标与边界

以 `taro/` 逐步恢复微信小程序功能；不保留其他平台的配置或占位实现。Java 产品 API 与 PostgreSQL 继续是唯一权威数据源。

基线固定为 Taro 4.2.1 与 React 18。`taro/` 使用独立 `package.json`、lockfile 和微信开发者工具配置。

## 已建立的目录

```text
taro/
├── config/                 微信小程序编译配置
├── src/
│   ├── app.tsx             应用入口
│   ├── app.config.ts       页面与窗口配置
│   └── pages/index/        迁移状态页
├── types/                  Taro 环境类型
├── project.config.json     微信开发者工具配置
└── package.json            独立依赖和命令
```

只创建当前能运行的文件。`features/`、`services/`、`platform/` 等目录在首个对应模块迁移时再创建。

## 迁移原则

1. **纵向迁移一个完整流程。** 每次包含页面、API schema、加载/空/错态和验收，不先批量重写 UI。
2. **先恢复纯逻辑，后接平台能力。** 根据服务端 schema 与 Git 历史恢复 contract、判分 payload 和 i18n 格式化逻辑；安全存储、离线数据库、文件和支付按微信能力重新实现。
3. **不降级安全边界。** API 响应仍做 schema 校验；生产 API 必须 HTTPS；完成令牌存储威胁评审前，不落盘 30 天 refresh token。
4. **保持幂等语义。** 可重放写请求继续携带稳定 `Idempotency-Key`；离线队列未迁移前只允许在线写入并明确提示失败。
5. **每阶段独立可验收。** 只有完成 schema、错误态和微信开发者工具冒烟后，功能才算恢复。

## 优先级与阶段

### 阶段 0：编译与运行基线（已完成）

- 固定 Taro/React 兼容版本，建立独立 lockfile。
- 接入类型检查和微信小程序构建。
- 保留一个无业务状态页验证 JSX/CSS 编译。

**门禁：** `npm run verify` 通过，微信开发者工具能打开状态页；当前状态页不得发布。

### 阶段 1：认证与公共数据层（P0）

- 实现 success/error envelope、超时、取消、401 和服务端错误文案。
- 迁移登录、邮箱验证码注册和 `/auth/me`。
- 在明确令牌威胁模型后选择微信会话方案；评审前 access token 仅驻留内存。
- 从现有 schema 中迁移首批实际使用的类型，不复制未使用 contract。

**门禁：** 微信开发者工具完成登录、刷新、退出、过期和停用账号用例；日志、普通 storage 和错误上报中均无 token。

### 阶段 2：高频学习主链路（P0）

依次迁移概览、题库列表和详情、题目详情、在线练习与结果。每个 feature 内聚页面、业务组件和请求 hook；通用 UI 只使用 Taro 组件与 CSS，重复出现后再提取。

**门禁：** 列表数量、排序、题目内容、答题 payload、进度和结果与服务端 contract 一致。

### 阶段 3：题库管理与辅助功能（P1）

迁移题库、题组和题目编辑，以及收藏、搜索、分析、账号资料、语言和隐私页面。写操作保留服务端校验和 `Idempotency-Key`。

### 阶段 4：导入与媒体（P1）

使用微信文件/图片选择能力与 multipart 上传。导入进度先轮询 durable events；鉴权媒体先下载到平台临时文件再展示。

**门禁：** 支持格式、10 MiB 上限、取消、失败重试、进度、临时文件清理和鉴权行为通过真机验证。

### 阶段 5：离线缓存与同步（P2）

只缓存已证明需要离线的题库和进行中练习；超出微信 storage 能力时维持在线模式。确认需求后再接入顺序 outbox、稳定幂等键、失败重试和 pull anchor。

### 阶段 6：支付与切换（P2）

单独设计微信支付；没有实现时保持入口隐藏。高频链路稳定后再排期 Organization 学习小组。

## 发布前阻塞项

- 配置正式微信 appid 和 HTTPS request/upload/download 合法域名，不提交密钥。
- 确定微信身份、令牌存储和支付方案。
- 完成登录、练习、上传、离线恢复和支付真机验收。
- 其他平台留到明确提出需求后再设计，不预留空实现。
