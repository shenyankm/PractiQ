## 本轮定位到的主要成本

- 小样本主要花在准备及腾讯处理（约 6.9–7.3 s）和模型 SDK 请求（约 4.5–4.7 s）。
  原生完整练习恢复约几十毫秒，继续缩短本地 SQL 对这组整体等待的收益有限。
- 根据 stage 时间戳，服务图本身约 11.49–12.18 s；点击至结果可见另多约 0.84–3.23 s。
  当前活跃任务每 3 s 轮询，与这个量级一致；差值也含上传、排队、checkpoint、HTTP 和渲染，
  **未把全部差值归因于轮询**。若继续优化，应先单独量出终态完成至 UI 可见的等待。
- 服务主进程采样 RSS 峰值约 185.8 MiB（194,789,376 B），438 次 ps 采样，间隔至少 100 ms。
  不含 Chromium、原生进程、数据库、broker 和提取子进程，也可能漏掉短峰值；不是整机峰值。
- 已建立当前版本基线。没有相同全链路负载的历史版本对照，不能宣称历次局部优化叠加后的整体提升。
