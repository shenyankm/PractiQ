# OCR, exam-results and resource-export performance — October 30, 2026

Baseline: `dc5023e59947cbc219f00df6c867339a488ec863` (PR #476).
This follow-up covers four recommendations from the next main-branch review.

## Scope

1. Skip neighbor OCR reads when PRIMARY has no questions or lacks stable IDs
   required by context enrichment. Used evidence retains ordered verified reads.
2. Memoize saved exam/practice result aggregates while editing manual scores or
   reasons. Attempts, mode and submission changes invalidate the memo; current
   question state and explicit grading/retry actions remain live.
3. Retain the page projection already produced by each OCR response validator.
   PRIMARY and enrichment responses validate independently. The graph consumes
   the projection and applies review flags to it, without mutating the response
   or using a cross-request cache. Explicit `page_result()` still revalidates.
4. Reuse local `read_asset` size/hash verification in the ZIP export loop and
   retain full media validation. External ZIP import still checks size, SHA-256,
   media format and audio segments before importing anything.

No dependency, database/backup format, credential namespace, public schema,
model-call trigger, provider concurrency or unknown-result recovery changes.
The previously rejected OCR-merge concurrency and ZIP compression-level changes
are not included.

## Measurement method

Apple M4 / arm64 macOS, Python 3.14.7, Node 22.23.2 and Rust 1.98.1.
All measured inputs are synthetic. Probes use temporary local storage and model
substitutes, never user databases or live providers. Garbage collection remains
enabled and OS file caches are warm. Raw reports retain all measured samples.

- [Service report](../../evidence/2026-10-30-followup-performance/server.json):
  complete `_vision` nodes, including real bounded/checksummed local artifact
  reads, prompt construction, substitute response validation and publication.
  The Git baseline supplies both its node and OCR model class; model JSON
  schemas and complete returned output hashes must match. Three serial
  before/after pairs each use one warmup and seven measured calls.
  Table cases use retained JSON evidence without image-crop bytes; their timing
  measures projection/validation work rather than image processing.
  Each substitute validates one response; provider adapters, persisted model-call
  receipts and their additional validation are outside the measurement. The
  shared LLM boundary still validates both live and saved responses.
- [App summary](../../evidence/2026-10-30-followup-performance/app.json) and raw
  `app-before-{1,2,3}.json` / `app-after-{1,2,3}.json` in that directory: three
  fresh process pairs in AB/BA/AB order, using the same probe and locked
  dependencies. Each workload uses one warmup and seven clear-and-type
  sequences. Times sum React development/JSDOM Profiler render durations for
  clearing and typing sixteen characters. Full result-panel text and draft
  hashes must match. Getter counters measure noncurrent answer reads without
  mock functions in the timed path. Setup, assertions and hashing are excluded.
- [Native report](../../evidence/2026-10-30-followup-performance/native.json):
  release-mode local resource read, bounded size/hash verification and complete
  PNG validation. The before path runs the unchanged import verification helper
  after `read_asset`; the after path runs media validation after that same read.
  This isolates the removed duplicate hash, rather than compiling the whole
  historical exporter. Three process-local alternating pairs each use one
  warmup and seven samples. Both variants must return identical bytes/duration.

These scopes do not measure peak memory, provider latency, full document imports, production
keyboard latency, native WebView rendering, complete ZIP export or device audio.
Work-count and output-equivalence assertions are the stable acceptance evidence;
small absolute timing differences remain sensitive to host load.

| Exam reason editing: 20 questions | 8.75 / 8.64 | Noncurrent answer reads 323 → 0 per sequence |
| Exam reason editing: 1,000 questions | 10.40 / 8.10 | Noncurrent answer reads 16,983 → 0 per sequence |
| Resource read/verify: 49,348-byte PNG | 0.078 / 0.090 | Remove one SHA-256 pass after the verified read; retain complete media validation |

All compared outputs match. The 20-question App difference is too small to treat
as a meaningful user-visible win. The small PNG median regressed by 0.012 ms;
no latency win is claimed there. Avoiding repeated work is the stable result for
these small cases. Large-workload measurements establish local component
improvements, not total import/export or native input latency.

## Reproduce

Use an existing Python 3.14+ interpreter with locked service/dev dependencies,
locked App dependencies, and a macOS native toolchain. From the repository root:

```sh
cd server
AI_READ_ONLY=1 AI_SERVICE_TOKEN=synthetic-benchmark-only PYTHONPATH=src:. \
  "$AI_PYTHON" scripts/benchmark_ocr_projections.py --baseline dc5023e5 \
  --output /tmp/practiq-ocr-projections-new.json
cd ..
(cd app && PRACTIQ_EXAM_BENCH_OUTPUT=/tmp/practiq-exam-new.json \
  npm exec -- vitest run src/ExamResults.performance.test.tsx)
PRACTIQ_RESOURCE_BENCH_OUTPUT=/tmp/practiq-resources-new.json \
  TAURI_CONFIG='{"bundle":{"resources":[]}}' \
  cargo test --locked --release --manifest-path app/src-tauri/Cargo.toml --lib \
  resource_export_read_benchmark -- --ignored --nocapture
```

For the App baseline, extract `git archive dc5023e5 app shared` into a temporary
directory, link its `app/node_modules` to the installed locked dependencies and
copy the same `ExamResults.performance.test.tsx` probe into its `app/src/`.
Run Vitest from each App directory in AB/BA/AB process order with distinct output
paths. Compare probe/output hashes before interpreting timing differences.
