# 性能优化与合成压测记录

2026-09-21；首轮基线为 `d374cc09cf2ba1cf9cb3b5d1a52eac79cfa34ba1`，首轮优化对应 `da05ded`，数据在提交前从本地工作区采集。后续 PR #39 评审修复的复测单列于下方。本次验证未部署、未调用外部模型、未访问个人题库。

主要收益来自消除重复题目遍历、重复快照解析和全量响应；服务端减少连接建立与空闲轮询，并移除页图传输中的 Base64。所有原始结果保存在 [performance-20260921.json](performance-20260921.json)。

## 实施范围

| 路径 | 变更及保留的约束 |
| --- | --- |
| 题库读取 | 每次操作建立借用索引，按题库和根题 ID 限定 SQL 读取范围；题目页每页 30 个根题或完整题组，返回总数和有效页偏移。保留排序、子题命中带入整组、Unicode 内容搜索和删除后的页码回退。 |
| 练习快照和交卷 | 每次操作只解析一次冻结文档，复用索引；作答附加字段与收藏使用联表查询。保留不可变快照、交卷前答案隐藏和原有评分规则。 |
| 草稿 | `save_draft` 复用原事务、答案与期限校验，成功返回 `null`，省去完整 session 构造与传输。前端继续串行保存，切题、关闭和交卷等待保存完成。 |
| Markdown / 公式 | 对 `Content` 和 `Markdown` 使用 React `memo`；内容未变化时复用渲染，语言更新仍通过上下文生效。未添加依赖。 |
| AI 调度与 SQLite | 独立业务读连接复用，串行关闭游标以避免并发读取共享旧快照；写事务、checkpoint、Store 保持隔离。补建三个排序索引；队列优先使用事件唤醒，空闲等待最多 1 秒后兜底复查，保留启动恢复与停止逻辑。 |
| 提取进程传输 | 二进制页文件加有界 JSON 清单；主进程在线程中执行文件 I/O。校验文件类型、大小、页数、长度及符号链接，连续取消也等待文件操作结束再清理临时目录。 |

## 测试条件

- Apple M4，10 核，16 GiB；macOS 27.0（26A428），Python 3.14.7、Rust 1.98.1、Node.js 22.23.2。
- 桌面使用实际 `Store` 与临时 SQLite，Rust release 编译；计时包括操作与 JSON 序列化，不包括 Tauri 传输和 WebView 绘制。
- 修改前先测基线；优化后各组压测顺序运行，与构建、回归检查分开。未清除操作系统文件缓存，未限制机器资源，也未控制其他应用的后台活动。
- 桌面公共路径和 80 文档批次各测 3 次，报告中位数；100 次草稿报告 P95。样本量适合发现本次大幅开销变化，不能据此承诺生产延迟或容量。

## 桌面：5,000 题库、1,000 题考试

固定数据包含一个 20 题的小库、一个 4,980 题的大库，以及三场相同的 1,000 题自测。数据为简单判断题；复杂长材料、图片、公式的耗时需另测。

| 相同操作 | 优化前中位数 | 优化后中位数 | 耗时减少 |
| --- | ---: | ---: | ---: |
| 全部 5,000 题读取 | 7,224.99 ms | 213.41 ms | 97.0% |
| 从总库中读取 20 题的小库 | 205.07 ms | 1.47 ms | 99.3% |
| 读取 1,000 题 session | 95.00 ms | 9.90 ms | 89.6% |
| 原 `save_attempt` 保存并返回 session | 108.51 ms | 14.07 ms | 87.0% |
| 1,000 题交卷及本地判分 | 3,648.07 ms | 19.01 ms | 99.5% |

新 UI 路径另计：

- 首屏只请求 30 题，中位数 **2.64 ms**，响应 **19,955 B**。旧 UI 先取全部 5,000 题，响应 **3,355,601 B**；分页减少的内容仍可翻页访问。
- 新草稿命令中位数 **3.92 ms**，响应 **4 B**（`null`）；旧命令返回 **878,662 B** 的完整 session。二者执行相同写入校验，返回值契约不同。
- 连续写入 100 次，P50 **3.90 ms**、P95 **4.64 ms**。重开数据库后末次答案一致，三场交卷的 1,000 道题均得到预期分值。
- 前端回归模拟 100 次父组件更新：内容不变只解析一次 Markdown，内容变化后再解析一次。这是渲染次数验证，不是浏览器帧率测量。

## 服务端：真实 SQLite / LangGraph，合成模型

模型替身每次等待 100 ms 后返回固定合格结构；任务并发 **8**、单任务图并发 **2**、供应商并发上限 **16**、合成测试 RPM 上限 **100,000**。任务通过实际 API 函数提交，`/ok` 通过进程内 ASGI 访问，不包含网络或反向代理。

| 工作负载 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 80 文档批次耗时中位数 | 5.112 s | 4.170 s |
| 80 文档批次成功吞吐中位数 | 938.98 文档/分钟 | 1,151.17 文档/分钟 |
| 三轮各自 `/ok` P95 的范围 | 2.73–4.84 ms | 2.10–2.42 ms |
| 三轮完成 / 调用与用量条数 | 240 / 240 | 240 / 240 |

该合成负载吞吐增加 **22.6%**，批次耗时减少 **18.4%**。优化前各轮耗时 4.790 / 6.257 / 5.112 秒，优化后为 4.283 / 4.170 / 4.023 秒，保留全部样本，没有挑选最快轮次。

额外一次 **240 文档同时提交**的突发测试：240/240 完成，每任务恰有一条模型用量；总耗时 **12.132 s**，`/ok` P95 **2.01 ms**，任务队列等待中位数 **5.72 s**。该测试没有真实模型、文件存储网络或大 PDF 处理，不是生产容量验收。默认 `8×2` 未改变。

## 50 MiB 页图传输

分别在新进程中运行原 Base64 JSON 协议与新二进制协议，每个进程写入一次、读取三次。输入为 50 份各 1 MiB 的合成字节，验证还原字节完全一致；不包含 PDF 渲染、JPEG 解码或模型识别。

| 指标 | 原协议 | 新协议 |
| --- | ---: | ---: |
| 临时文件总字节 | 69,906,088 B | 52,429,338 B |
| 读取中位数 | 105.47 ms | 4.63 ms |
| 5 ms 监测间隔下事件循环最大延迟 | 103.21 ms | 0.68 ms |
| 独立测试进程峰值 RSS | 279.75 MiB | 142.22 MiB |

RSS 包含合成数据创建、协议写入及三次读取，不能当作整个服务及所有子进程的内存峰值。文件体积减少约 25%，测试进程峰值 RSS 减少约 49%。

## 复现

准备仓库锁定依赖和已有 Python 3.14+，从仓库根目录开始。三个基准使用临时目录，按顺序执行：

```sh
cd app/src-tauri
PRACTIQ_BENCH_OUTPUT=/tmp/practiq-desktop.json \
  cargo test --offline --release --lib performance::desktop_stress -- --ignored --nocapture

cd ../../server
PYTHONPATH=src:. /path/to/python3.14 scripts/benchmark_runtime.py \
  --documents 80 --rounds 3 --output /tmp/practiq-runtime.json
PYTHONPATH=src:. /path/to/python3.14 scripts/benchmark_runtime.py \
  --documents 240 --rounds 1 --output /tmp/practiq-runtime-burst.json
PYTHONPATH=src:. /path/to/python3.14 scripts/benchmark_preprocessing.py \
  --output /tmp/practiq-preprocessing.json
```

上述命令复现优化后路径；页图脚本内置原协议对照。桌面原始基线来自改动前同一 fixture 的公共操作；分页、轻量草稿和连续写入是新增测量，原版没有对应命令。报告保留原始基线与新结果。

## PR #39 评审修复

[评审指出](https://github.com/shenyankm/PractiQ/pull/39#discussion_r4063294424)：请求可能在 SQLite 已提交、尚未发送唤醒通知时被取消，单靠事件会使持久队列任务滞留。现在保留即时事件唤醒，并在空闲等待最多 1 秒后兜底复查队列；不增加配置项或改变任务、模型并发。

新增创建／恢复两个回归场景：先让调度器进入等待，再在真实事务提交后取消请求；只读观察，不通过其他请求、通知或重启解救任务。两个用例均在 `da05ded` 上超时失败，修复后均完成原 run，模型调用和用量没有重复。运行时与任务 API 的 46 项检查通过；全量 `make verify` 为 **525 项通过、94% 覆盖率**，macOS 重新打包及最终包内服务检查通过。

修复后先单独运行 80 文档 × 3 轮：全部 240 份完成，耗时为 **4.630 / 5.255 / 5.196 秒**，中位数 **5.196 秒 / 923.77 文档每分钟**。这组结果低于首轮记录，予以保留，不能沿用首轮 22.6% 的增益作为当前版本保证。

随后使用同一压测函数，将 `da05ded` 的调度循环与修复版按 AB / BA / AB 顺序交错执行；每轮各 80 文档，其他生产代码一致，沿用原脚本每轮独立 asyncio 事件循环。原循环三轮为 **5.286 / 6.088 / 5.252 秒**，修复版为 **5.106 / 4.886 / 5.171 秒**，中位数分别为 **5.286 / 5.106 秒**，全部 480 份完成。本机样本未显示兜底扫描造成吞吐下降，但不足以承诺稳定增益；构建和回归检查均在测量前结束。

首次交错实验复用了事件循环，出现 LangGraph 测试 Store 后台任务清理告警，其数据保留在 JSON 的 `reviewFix.sharedLoopDiagnostic`，仅作诊断；上述采用原脚本生命周期的对照没有该告警。所有复测与修复验证保存在 `reviewFix` 下，首轮历史数据未覆盖。
