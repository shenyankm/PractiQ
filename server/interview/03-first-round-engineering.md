# 一面：核心工程实现

这一组关注代码是否真正跑得稳。回答时先说实现，再解释原因。

## 11. 结构化输出如何降低模型格式错误？

**参考回答：**

- 调用模型时使用 Pydantic Schema 和 function calling，而不是解析自由文本 JSON。
- 公共模型默认 `extra="forbid"`，字段还有长度、范围、枚举和跨字段校验。
- 结构合法后继续做业务校验，例如选择题答案必须引用请求中的选项标签。

**常见追问：** Pydantic 能否保证答案语义正确？不能，它只收紧结构和可编码的业务规则。

## 12. 上传链路如何保证文件可信？

**参考回答：**

- 二进制文件由客户端直传预签名 PUT URL，应用不转发大文件。
- `DocumentReference` 携带对象键、声明大小和 SHA-256。
- 每次读取先 HEAD 校验大小，再读取并重新计算 SHA-256；不一致立即拒绝且不调用模型。
- 对象键按内容哈希组织，相同内容可复用已有对象。

**常见追问：** 预签名 URL 泄露有什么影响？它只有短 TTL，仍应避免记录完整 URL，并限制对象键和上传头。

## 13. 文本如何切分并处理边界重复？

**参考回答：**

- 默认目标大小为约 30,000 字符，优先识别阿拉伯数字或中文大题编号边界。
- 相邻块保留上一块最后一道题，降低题干在边界处被截断的风险。
- 合并时只比较相邻块的首尾题干规范化键，不做全局模糊去重，避免误删相似题。

**常见追问：** 没检测到题号怎么办？退化为固定字符窗口。

## 14. `Send` 和 `asyncio.gather` 分别用在哪里？

**参考回答：**

- 视觉单元和文本分片使用 `Send`，每个单元都是 Graph task，可独立记录结果和失败。
- OSS 批量 PUT/GET 使用 `_bounded_map`，内部是 `Semaphore + asyncio.gather`。
- 选择标准不是“哪个并发更快”，而是工作单元是否需要进入 Graph 的状态与恢复语义。

**常见追问：** 为什么不能对所有 OSS 请求直接无限制 `gather`？

## 15. 并行完成顺序不稳定，如何保证结果稳定？

**参考回答：**

- reducer 先累积并行节点结果。
- 合并前按视觉类型、页号或 chunk `index` 排序，不依赖完成顺序。
- 题组中的局部 `questionIndexes` 在合并时映射为全局索引。

**常见追问：** 稳定顺序为什么重要？它影响重试后结果一致性、前端展示和可复现评测。

## 16. 单个 OCR 或 chunk 失败时为什么不让整个任务失败？

**参考回答：**

- 每个单元的失败被转换为 `UnitFailure(stage, index, code, retryable)`。
- 仍有成功 chunk 时，系统返回可用题目并把状态标为 `PARTIAL`。
- 所有 chunk 失败、没有可提取文本或没有任何题目时才终止。

**常见追问：** 前端如何判断结果是否可用？同时看顶层状态、`processing` 计数、失败列表和 warnings。

## 17. 模型失败如何重试？

**参考回答：**

- 传输错误先分类：超时、连接错误、408/409/429 和 5xx 可退避重试，永久错误立即失败。
- 解析或业务校验失败时，把具体错误追加到消息中要求模型修正。
- 传输重试和输出修复共享最多四次调用预算，避免两层重试相乘。

**常见追问：** 为什么 409 可能重试？这是当前 provider 错误分类策略；若接入新供应商，应以其协议语义重新校准。

## 18. 为什么 Checkpoint State 不保存文件字节或模型对象？

**参考回答：**

- 大对象会放大 checkpoint、拖慢序列化和恢复，也容易超过状态存储限制。
- State 只保存 JSON 可序列化的 `objectKey`、SHA-256、媒体类型和大小。
- 原文件与中间文本、图片、分片存 OSS；节点使用引用按需读取并再次校验。

**常见追问：** OSS 对象被生命周期规则提前删除会怎样？应返回明确的对象不存在错误，因此生命周期至少要覆盖任务恢复窗口。

## 19. 如何测试这类 AI 工作流？

**参考回答：**

- 模型和 OSS 都使用 fake 或 monkeypatch，单元测试不访问真实外部服务。
- 测试覆盖 Schema、路由、重试上限、部分失败、稳定合并、文件上限和校验和边界。

**常见追问：** 哪类问题最值得写回归测试？曾导致错误路由、重复副作用或数据边界失守的问题。
